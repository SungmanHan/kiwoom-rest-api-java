# account — 계좌 조회

전부 `/api/dostk/acnt` (읽기 전용).

**계좌번호는 요청 body에 넣지 않습니다.** appkey(=토큰)에 귀속돼 서버가 알아서 판단합니다.

구현: [`KiwoomAccountService.java`](KiwoomAccountService.java)

## ⚠️ `kt00004.tdy_lspft`는 당일 실현손익이 아니다

**당일 매도가 있어도 반영되지 않습니다.** (실측 2026-07-31)

매도가 있는 날은 직접 재계산해야 합니다:

```
kt00017.sell_amt > 0 인가?
  → ka10076 (당일 체결 목록) 에서 종목코드 수집
  → 각 종목 ka10077 호출 → tdy_rlzt_pl 합산
```

매도가 없는 날은 `tdy_lspft`(=0)가 정확하므로 추가 호출이 필요 없습니다. 조건부로 돌리세요.

### 여기서 0은 두 가지 의미다

`sell_amt > 0` 을 확인하고 진입했는데 합계가 0으로 나왔다면, 그건 "매도 없음"일 수 없습니다. **반드시 조회 실패**입니다. 로그를 남기지 않으면 원래 버그(`tdy_lspft`)와 구분이 안 됩니다.

```java
if (fills == null) {
    log.warn("[계좌] ka10076 조회 실패 — 0으로 표시되나 매도 없음이 아니라 조회 실패임");
    return 0L;
}
```

## 보유종목 코드에는 `A` 접두사가 붙는다

`kt00018` 응답의 `stk_cd`는 `"A005930"` 형태입니다. 다른 TR의 `_AL`/`_NX` **접미사**와 반대 방향이니 둘 다 처리하세요.

```java
raw.startsWith("A") ? raw.substring(1) : raw
```

---

## `dmst_stex_tp` — 숫자가 아니라 문자열

`stex_tp`("1"/"2"/"3")와 달리 계좌 TR은 **`"KRX"` / `"NXT"` / `"SOR"`** 문자열입니다. 시간 경계는 동일하므로 판정 함수는 공유하세요.

```java
정규장(09:00~15:30) → "KRX" / 그 외 → "NXT"
```

### 단, 매도 직전 잔고 확인은 KRX 고정 권장

NXT 조회 시 목록 필터가 걸릴 수 있어, **실제 매도 가능 수량(`trde_able_qty`) 재확인**은 거래소를 KRX로 고정하는 편이 안전했습니다.

## 호출 비용을 나누세요

`kt00018` 하나만 필요한 호출부(매도 전 잔고 확인 등)가 잔고카드용 4종 세트를 통째로 부르면 **API 3콜이 낭비**됩니다.

```java
fetchBalance()                    // 4종 TR — 잔고 카드용
fetchBalance(true)                // + kt00016 기간손익 + 당일 실현손익 재계산
fetchHoldings()                   // kt00018 단독 — 매도 전 수량 확인용
```

`kt00018`은 **1회 호출로 총계와 보유목록을 동시에** 파싱할 수 있습니다. 두 번 부르지 마세요.

---

## 부분 실패를 구분하세요

4종 TR 중 일부만 실패했을 때 "전체 실패"로 처리하면 멀쩡한 데이터를 버리게 됩니다.

- `Optional.empty()` = **조회 실패**
- 빈 리스트 present = **실보유 0종목**

이 둘이 뭉개지면 "잔고가 비었다"와 "조회가 안 됐다"를 구분할 수 없습니다.
