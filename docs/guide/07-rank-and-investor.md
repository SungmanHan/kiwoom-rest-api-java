# 키움 REST API Java로 거래대금 순위·기관·외인 수급 조회하기 (ka10030, ka10044, ka10034)

> 키움 REST API Java 학습 시리즈 7/11편

## 이번 글에서 배울 것

- 순위 계열 TR이 거래소를 고르는 방식 (`stex_tp` 파라미터)과 응답 종목코드 접미사 처리
- `ka10030` 으로 거래대금 상위 종목을 서버 사이드 필터로 받는 법
- `ka10044`(기관)와 `ka10034`(외인)의 파라미터 체계 차이
- 빈 문자열·단위(백만원, 주, 금액)가 만드는 파싱 함정
- 이번 편 재료에 없는 TR(`ka10063`, `ka10051`)의 범위

## 왜 필요한가

순위·수급 TR은 "어떤 종목들을 볼 것인가"를 정하는 입구입니다. 종목 하나를 조회하는 TR과 달리 한 번에 100행 안팎을 돌려주므로, 파라미터 조합과 응답 파싱이 조금만 어긋나도 데이터 전체가 조용히 틀어집니다. 이 글은 `rank` 모듈의 README를 기준으로 그 지점들을 짚습니다.

## 실제 코드 살펴보기

### 순위 계열 TR 한눈에 보기

| TR | 용도 | 엔드포인트 | LIST 키 |
|---|---|---|---|
| `ka10030` | 당일 거래량/거래대금 상위 | `/rkinfo` | `tdy_trde_qty_upper` |
| `ka10032` | 거래대금 상위 (현재/전일 순위) | `/rkinfo` | `trde_prica_upper` |
| `ka10034` | 외인 기간별 매매 상위 | `/rkinfo` | `for_dt_trde_upper` |
| `ka10044` | 일별 기관매매 종목 | `/mrkcond` | `daly_orgn_trde_stk` |
| `ka10016` | 신고저가 | `/stkinfo` | `ntl_pric` |
| `ka00198` | 실시간 종목조회 순위 (관심도) | `/stkinfo` | `item_inq_rank` |

`ka10044` 만 엔드포인트가 `/mrkcond` 로 다릅니다. 나머지 순위 TR의 `/rkinfo` 를 그대로 복사하면 호출이 어긋납니다.

거래소 선택은 전부 **`stex_tp` 파라미터 방식**입니다(종목코드 접미사 방식이 아님). 다만 **응답의 `stk_cd` 에는 접미사가 붙어서** 옵니다.

### ka10030 — 거래대금 상위 조회

```java
Map.of(
  "mrkt_tp",       "000",     // 전체
  "sort_tp",       "3",       // 3 = 거래대금 정렬
  "mang_stk_incls","16",      // 관리종목 등 복합 제외 코드
  "crd_tp",        "0",
  "trde_qty_tp",   "0",
  "pric_tp",       "7",
  "trde_prica_tp", "5000",    // ★ 거래대금 하한 게이트 — 5000 = 500억
  "mrkt_open_tp",  "0",       // 0=전체 / 1=장중
  "stex_tp",       "3"        // KRX+NXT 통합
)
```

`trde_prica_tp` 가 서버 사이드 필터입니다. 여기서 걸러 받으면 클라이언트에서는 100~200종목만 다루면 됩니다. 응답의 `trde_amt` 단위는 **백만원**입니다(검증: 삼성전자 11,526,863 → 11.5조원).

### ka10034 / ka10044 — 외인 / 기관 기간별

두 TR은 같은 개념을 조회하지만 **파라미터 체계가 다릅니다.**

```java
// ka10034 (외인) — 기간을 코드로
Map.of("mrkt_tp","000", "trde_tp","2",       // 2 = 순매수
       "dt", "1",                             // 1/2/3/4 = 5일/10일/20일/60일
       "stex_tp","3")
```

```java
// ka10044 (기관) — 기간을 날짜 범위로
Map.of("strt_dt","20260805", "end_dt","20260810",
       "trde_tp","2",
       "mrkt_tp","001",        // ⚠️ 001=KOSPI / 101=KOSDAQ — 시장별 호출 필요
       "stex_tp","3")
```

| | ka10034 | ka10044 |
|---|---|---|
| 기간 지정 | `dt` 코드 | `strt_dt`/`end_dt` |
| 시장 | `000` 한 번 | `001`+`101` 각각 |
| 값 | `netprps_qty` (수량, 주) | `netprps_amt` (금액) |
| 슬롯당 호출 | 4회 | 8회 (4기간 × 2시장) |

수량과 금액을 섞어서 비교하지 마세요.

### 참고: ka10032, ka10016

`ka10032` 는 `now_rank` / `pred_rank` 가 함께 오며, `pred_rank - now_rank > 0` 이면 순위 상승입니다. `ka10016` 은 기간(`dt`: 5/20/60/120/250)별로 각각 호출해야 합니다.

### 응답 종목코드 접미사 제거

`stex_tp=3` 으로 요청하면 응답 `stk_cd` 가 `"005930_AL"` 형태입니다. `ka00198` 만 예외적으로 접미사가 없습니다.

```java
if (raw.endsWith("_AL") || raw.endsWith("_NX")) raw = raw.substring(0, raw.length() - 3);
```

## 실제 응답 예시 (ka10030)

```jsonc
{
  "tdy_trde_qty_upper": [            // ← 100행
    {
      "stk_cd": "005930_AL",         // ← 통합 호출이라 접미사가 붙었다
      "stk_nm": "삼성전자",
      "cur_prc": "-222500",          // 부호 = 등락 방향
      "pred_pre": "-3500", "pred_pre_sig": "5", "flu_rt": "-1.55",
      "trde_qty": "37415765",
      "pred_rt": "+100.00",          // 전일 거래량 대비
      "trde_tern_rt": "+0.64",       // 회전율
      "trde_amt": "8419636",         // ← 백만원 → 8.4조원

      "opmr_trde_qty": "",           // 장중  ┐
      "af_mkrt_trde_qty": "",        // 시간외 ├ 조건 안 맞으면 빈 문자열
      "bf_mkrt_trde_qty": ""         // 장전   ┘
    }
  ],
  "return_code": 0
}
```

`ka10034` 응답에서는 `netprps_qty` 가 **수량(주)** 이며 금액이 아닙니다. 상위를 ETF가 차지하는 경우가 많아 개별 종목만 필요하면 필터링이 필요합니다.

## 여기서 주의해야 할 점

- **`stex_tp` 와 접미사의 비대칭**: 유니버스를 `stex_tp=3`(통합)으로 뽑고, 그 종목의 호가(`ka10004`)·차트(`ka10081`)는 접미사 없이 조회하면 KRX만 보게 됩니다. 선정 기준과 상세 조회의 거래소가 달라지므로 의도한 게 아니면 맞추세요.
- **접미사를 빼먹으면 조용히 실패**: `_AL`/`_NX` 를 제거하지 않으면 예외 없이 Map lookup이 전부 실패합니다. 순위 데이터가 통째로 안 붙는데 에러는 나지 않습니다.
- **빈 문자열 응답**: `opmr_*` / `af_mkrt_*` / `bf_mkrt_*` 는 `mrkt_open_tp` 설정에 따라 0이 아니라 **빈 문자열**로 옵니다. 숫자 파서에 그대로 넣으면 예외가 납니다.
- **단위 혼용**: `trde_amt` 는 백만원, `ka10034` 의 `netprps_qty` 는 주, `ka10044` 의 `netprps_amt` 는 금액입니다.
- **필수 파라미터 캐스케이드**: 위 표처럼 TR마다 요구하는 파라미터 조합이 다르고(`ka10044` 는 시장별 `mrkt_tp` 와 날짜 범위가 함께 필요), 한 항목의 값이 다른 항목의 의미를 바꿉니다(`mrkt_open_tp`, `trde_prica_tp` 등). 재료에는 "어떤 파라미터가 누락되면 어떤 오류가 나는지"가 적혀 있지 않으므로, 필수 여부의 상세는 확인이 필요합니다. 다른 TR의 파라미터 세트를 복사해 쓰지 말고 TR별로 세트를 따로 정의하세요.
- **`ka10063`(장중 수급), `ka10051`(시장 전체 수급)**: 이번 편 재료(`rank/README.md`)에는 이 두 TR의 파라미터·응답 설명이 없습니다. 이 글에서는 다루지 않으며, 사용 전 공식 문서나 해당 모듈 코드의 확인이 필요합니다.

## 이번 글 정리

- 순위 TR은 `stex_tp` 로 거래소를 고르고, 응답 `stk_cd` 의 `_AL`/`_NX` 접미사는 직접 제거한다.
- `ka10030` 은 `trde_prica_tp` 서버 필터로 응답 크기를 줄인다.
- `ka10034`(외인, 수량)와 `ka10044`(기관, 금액)는 기간 지정·시장 지정·값의 단위가 모두 다르다.
- 빈 문자열과 단위 차이는 예외 없이 틀린 결과를 만들 수 있으니 파서에서 먼저 방어한다.
