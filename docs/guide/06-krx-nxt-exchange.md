# 키움 REST API Java 연동 6편 — KRX / NXT 거래소 구분 (stex_tp, _AL 접미사)

> 키움 REST API Java 학습 시리즈 6/11

같은 종목 조회인데 어떤 TR은 `stex_tp` 로, 어떤 TR은 종목코드 뒤 `_AL` 로 거래소를 고릅니다. 잘못 넣어도 에러가 나지 않아서 결과가 비어 있거나 엉뚱한 거래소 데이터가 와도 알아채기 어렵습니다. 이번 글에서는 거래소를 고르는 두 가지 방식과, 응답 종목코드에 붙는 접미사 처리를 정리합니다.

## 이번 글에서 배울 것

1. 키움 API가 다루는 두 거래소(KRX, NXT)와 운영 시간대
2. 거래소를 고르는 두 가지 메커니즘: `stex_tp` 파라미터 vs 종목코드 접미사
3. 시간대로 거래소를 결정하는 `StexTpResolver` 코드
4. 응답 `stk_cd` 에 붙는 `_AL` / `_NX` 접미사 처리
5. 계좌·주문 TR은 또 다른 파라미터(`dmst_stex_tp`)를 쓴다는 점

## 왜 필요한가

키움 REST API는 한국거래소(KRX)와 넥스트레이드(NXT) 두 거래소의 데이터를 모두 제공합니다. 시간대에 따라 열려 있는 거래소가 다릅니다.

```
08:00 ─────── 09:00 ─────────────── 15:30 ─────────── 20:00
  │ 프리마켓   │       정규장         │    애프터마켓    │
  │   NXT     │        KRX          │       NXT       │
```

정규장(09:00~15:30)에는 KRX 데이터를, 그 외 시간에는 NXT 데이터를 봐야 하는 경우가 많습니다. 그래서 호출하는 시점마다 거래소 값을 올바르게 채우는 일이 필요합니다.

## 구조 다이어그램

거래소를 고르는 방식은 TR 종류에 따라 세 갈래입니다.

```
                        ┌─ 랭킹·시장 단위 TR ──▶ stex_tp 파라미터 ("1" / "2" / "3")
 거래소 선택 ──────────┼─ 단일 종목 TR ───────▶ stk_cd 접미사 (plain / _NX / _AL)
                        └─ 계좌·주문 TR ───────▶ dmst_stex_tp ("KRX" / "NXT" / "SOR")
```

| 유형 | 방법 | 값 |
|---|---|---|
| 랭킹·시장 단위 TR | `stex_tp` 파라미터 | `1`=KRX / `2`=NXT / `3`=통합(SOR) |
| 단일 종목 TR | `stk_cd` 접미사 | plain=KRX / `_NX`=NXT / `_AL`=통합 |
| 계좌·주문 TR | `dmst_stex_tp` | `"KRX"` / `"NXT"` / `"SOR"` (문자열) |

- `stex_tp` 방식: ka10030, ka10032, ka10034, ka10044, ka10016, ka10054, ka10063, ka10051, ka90001, ka90002
- 접미사 방식: ka10001, ka10004, ka10046, ka10080, ka10081, ka10082, ka10083
- `dmst_stex_tp` 방식: kt00018, kt00004, kt10000, kt10003, kt00007 등

## 실제 코드 살펴보기

시간대에 따라 `stex_tp` 를 결정하는 코드입니다. 전 TR 공통으로 쓰는 단일 기준(SSoT)입니다.

```java
  /**
   * 키움 거래소 구분(stex_tp) 시간대별 결정.
   *
   * <p>키움 API 거래소 코드:
   * <ul>
   *   <li>{@code "1"} — KRX 한국거래소 (정규장 09:00~15:30)</li>
   *   <li>{@code "2"} — NXT 넥스트레이드 (프리마켓 08:00~09:00, 애프터마켓 15:30~20:00)</li>
   *   <li>{@code "3"} — KRX+NXT 통합</li>
   * </ul>
   *
   * <p>정규장 시간대(09:00~15:30)에는 KRX 데이터를, 그 외 시간(NXT 단독 운영 시간)에는
   * NXT 데이터를 조회한다. {@code 15:30} 마감 시점은 KRX 종료로 간주(NXT 분기).
   *
   * <p>KST 명시 — JVM default zone 의존 방지 (Audit-F3, 2026-05-27).
   *
   * @return stex_tp 코드 ({@code "1"} KRX 또는 {@code "2"} NXT)
   */
  /**
   * 현재 시각이 KRX 정규장(09:00~15:30 KST) 이내인지 판정.
   *
   * <p>stex_tp("1"/"2") 와 dmst_stex_tp("KRX"/"NXT") 는 값 표현이 다르나 시간 경계는 동일 →
   * 두 계열 모두 이 메서드를 SSoT 로 사용한다.
   * KST 명시 — JVM default zone 의존 방지 (Audit-F3, 2026-05-27).
   */
  public static boolean isKrxRegularHours() {
    LocalTime now = LocalTime.now(ZoneId.of("Asia/Seoul"));
    return !now.isBefore(LocalTime.of(9, 0)) && now.isBefore(LocalTime.of(15, 30));
  }

  private static String resolveStexTp() {
    return isKrxRegularHours() ? "1" : "2";
  }
```

## 코드 한 부분씩 설명

**`isKrxRegularHours()`**
- 현재 시각이 09:00 이상, 15:30 미만이면 `true` 입니다. 15:30 정각은 KRX 종료로 보아 NXT 쪽으로 분기됩니다.
- `stex_tp`(`"1"`/`"2"`)와 `dmst_stex_tp`(`"KRX"`/`"NXT"`)는 값 표현만 다르고 시간 경계는 같습니다. 그래서 판정 함수 하나를 두 계열이 함께 씁니다.

**`resolveStexTp()`**
- 판정 결과를 `stex_tp` 값(`"1"` 또는 `"2"`)으로 바꿉니다. 통합(`"3"`)은 이 메서드가 돌려주지 않습니다. 통합이 필요하면 호출하는 쪽에서 직접 지정합니다.

**`ZoneId.of("Asia/Seoul")`**
- `LocalTime.now()` 만 쓰면 JVM 기본 타임존을 따릅니다. 서버 타임존이 KST가 아니면 경계가 어긋나므로 KST를 명시합니다.

## 응답 코드 접미사 처리

요청뿐 아니라 응답의 종목코드에도 접미사가 붙습니다.

- `stex_tp=3` 으로 요청하면 응답 `stk_cd` 가 `"005930_AL"` 로 옵니다.
- NXT 시간대에 호출하면 `"005930_NX"` 로 옵니다.

6자리 코드를 키로 쓰는 `Map` 조회는 **전부 조용히 실패**합니다. 예외도 나지 않고 결과가 그냥 비어 있습니다. 응답을 받자마자 접미사를 떼어 주세요.

```java
if (raw.endsWith("_AL") || raw.endsWith("_NX")) raw = raw.substring(0, raw.length() - 3);
```

접미사가 붙는 곳은 종목코드만이 아닙니다. `ka10051` 의 업종코드(`inds_cd`)도 같습니다(2026-05-28 실측, 문서에 없는 동작).

| `stex_tp` | `inds_cd` |
|---|---|
| 1 (KRX) | `001` |
| 2 (NXT) | `001_NX` |
| 3 (통합) | `001_AL` |

종합 행을 `equals("001")` 로 찾으면 통합 호출에서 못 찾습니다. `equals` 또는 `startsWith("001_")` 로 접두 매칭하세요.

## 여기서 주의해야 할 점

**1. 접미사 방식 TR에 `stex_tp` 를 넣어도 에러가 나지 않습니다.**
ka10001, ka10004, ka10046, ka10080~83 같은 단일 종목 TR은 `stex_tp` 를 **조용히 무시**합니다. 거래소를 바꿨다고 생각했지만 실제로는 바뀌지 않은 상태가 됩니다. TR이 어느 방식인지 먼저 확인하세요.

**2. 응답의 종목코드 접미사를 떼지 않으면 조회가 전부 빈 결과가 됩니다.**
`_AL`, `_NX` 가 붙은 코드로 6자리 키 Map을 조회하면 예외 없이 실패합니다.

**3. 계좌 TR은 접미사가 아니라 접두사입니다.**
`kt00018` 보유목록의 `stk_cd` 는 `"A005930"` 형태입니다. 앞의 `A` 를 떼야 합니다.

**4. 계좌·주문 TR의 `dmst_stex_tp` 는 숫자가 아니라 문자열입니다.**
`"KRX"` / `"NXT"` / `"SOR"` 를 씁니다. `kt00007`(체결내역)을 과거 일자로 조회할 때는 와일드카드 `"%"` 를 씁니다.

**5. NXT 구간에서는 시장가 주문이 거부됩니다.**
저녁 NXT 구간에서 `trde_tp=3`(시장가)은 `407022` 로 거부됩니다. 지정가(`trde_tp=0`)만 됩니다.

**6. 모의투자 서버는 NXT를 지원하지 않습니다.**
`mockapi.kiwoom.com` 은 KRX만 다룹니다. NXT 동작은 운영 서버에서만 확인할 수 있습니다.

**7. 통합(`_AL`)으로 바꾸면 호가 잔량이 달라집니다.**
`ka10004` 를 KRX에서 `_AL` 로 바꾸면 호가 잔량이 늘어납니다. 잔량을 기준으로 한 임계값을 쓰고 있다면 소스만 바꾸지 말고 임계값을 먼저 다시 맞춰야 합니다.

## 이번 글 정리

| 항목 | 핵심 |
|---|---|
| 시간 경계 | 09:00 이상 15:30 미만 = KRX, 나머지 = NXT |
| 랭킹·시장 TR | `stex_tp` = `1` / `2` / `3` |
| 단일 종목 TR | `stk_cd` 접미사 — plain / `_NX` / `_AL` (`stex_tp` 는 무시됨) |

| 응답 처리 | `_AL` / `_NX` 접미사 제거, 계좌 TR은 `A` 접두사 제거 |
| 타임존 | `ZoneId.of("Asia/Seoul")` 명시 |
