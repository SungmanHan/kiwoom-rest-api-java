# 키움 REST API Java 계좌 조회 — 잔고·예수금·평가 현황 가져오기 (kt00018, kt00001, kt00004)

> 키움 REST API Java 연동 시리즈 8/11편

## 이번 글에서 배울 것

- 계좌 조회 TR 3종(`kt00018`, `kt00001`, `kt00004`)이 각각 무엇을 돌려주는지
- 계좌번호를 요청 body에 넣지 않는 이유
- `dmst_stex_tp`가 숫자가 아니라 문자열인 이유와 거래소 값 고르는 법
- 응답 종목코드의 `A` 접두사 처리
- 호출 비용을 나누고, 부분 실패를 구분하는 설계
- 계좌번호·잔고를 로그와 저장소에 남기지 않는 방법

## 왜 필요한가

앞선 글에서 인증과 TR 호출 구조를 다뤘다면, 이번 글은 그 위에서 **내 계좌의 상태를 읽는** 단계입니다. 계좌 관련 TR은 전부 `/api/dostk/acnt` 엔드포인트 하나를 쓰고, **읽기 전용**입니다. 데이터를 바꾸는 호출이 없으므로 부담 없이 실험해 볼 수 있지만, 응답에 민감한 정보가 그대로 담기므로 다루는 방식에는 주의가 필요합니다.

구현 코드는 `KiwoomAccountService.java`에 있습니다.

## 실제 코드 살펴보기

### 계좌 조회 TR 목록

| TR | 용도 | 핵심 파라미터 | 핵심 응답 |
|---|---|---|---|
| **kt00018** | 계좌평가잔고내역 (총계 + 보유목록) | `qry_tp="1"`, `dmst_stex_tp` | `acnt_evlt_remn_indv_tot[]`, `tot_evlt_amt`, `tot_prft_rt` |
| **kt00001** | 예수금 상세 | `qry_tp="3"` | `entr`, `ord_alow_amt`, `100stk_ord_alow_amt`, `d2_entra`, `ch_uncla` |
| **kt00004** | 계좌평가현황 | `qry_tp="0"`, `dmst_stex_tp` | `prsm_dpst_aset_amt`, `tdy_lspft`, `lspft_rt` |
| **kt00017** | 계좌별 당일현황 | (없음) | `buy_amt`, `sell_amt`, `cmsn`, `tax` |
| **kt00016** | 일별계좌수익률상세 (기간 손익) | `fr_dt`, `to_dt` (YYYYMMDD) | `evltv_prft`, `prft_rt`, `invt_bsamt` |
| **ka10076** | 당일 체결 목록 | `qry_tp="0"`, `sell_tp="0"`, `stex_tp="0"` | `cntr[]` |
| **ka10077** | 종목별 당일 실현손익 | `stk_cd` | `tdy_rlzt_pl` |

이 글의 중심은 위 표의 **kt00018(잔고 조회) · kt00001(예수금 조회) · kt00004(평가 조회)** 세 가지입니다. 나머지 TR은 당일 손익을 보정할 때 함께 쓰이며, 아래 주의 사항에서 다룹니다.

### 계좌번호는 body에 넣지 않는다

가장 먼저 눈에 띄는 점은 **요청 body에 계좌번호가 없다**는 것입니다. 계좌는 appkey(=토큰)에 귀속되어 있어서 서버가 알아서 판단합니다. 그래서 요청 코드에 계좌번호를 다룰 일이 없고, 그만큼 노출 면적도 줄어듭니다.

### 호출 비용을 나눈 메서드 구성

`kt00018`만 필요한 호출부가 여러 TR을 묶은 세트를 통째로 부르면 **API 3콜이 낭비**됩니다. 그래서 용도별로 메서드를 나눕니다.

```java
fetchBalance()                    // 4종 TR — 잔고 카드용
fetchBalance(true)                // + kt00016 기간손익 + 당일 실현손익 재계산
fetchHoldings()                   // kt00018 단독 — 매도 전 수량 확인용
```

`kt00018`은 **1회 호출로 총계와 보유목록을 동시에** 파싱할 수 있습니다. 같은 값을 얻으려고 두 번 부르지 마세요.

## 여기서 주의해야 할 점

### 1. kt00018 잔고 조회: 종목코드에 `A` 접두사가 붙는다

`kt00018` 응답의 `stk_cd`는 `"A005930"` 형태입니다. 다른 TR에서 쓰던 `_AL`/`_NX` **접미사**와는 반대 방향(앞에 붙음)이니, 두 경우를 모두 처리해야 합니다.

```java
raw.startsWith("A") ? raw.substring(1) : raw
```

### 2. 계좌 TR의 `dmst_stex_tp`는 문자열 (kt00018·kt00004)

`stex_tp`("1"/"2"/"3")와 달리 계좌 TR은 **`"KRX"` / `"NXT"` / `"SOR"`** 문자열을 씁니다. 시간 경계는 동일하므로 판정 함수는 공유하세요.

```java
정규장(09:00~15:30) → "KRX" / 그 외 → "NXT"
```

> 위 블록은 재료 README의 규칙 요약이며 실제 메서드 시그니처가 아닙니다. 구현은 `KiwoomAccountService.java`를 확인하세요.

단, 매도 직전에 **실제 매도 가능 수량(`trde_able_qty`)을 재확인**할 때는 거래소를 KRX로 고정하는 편이 안전했습니다. NXT로 조회하면 목록에 필터가 걸릴 수 있기 때문입니다.

### 3. `kt00004.tdy_lspft`는 당일 실현손익이 아니다

가장 조심해야 할 함정입니다. **당일 매도가 있어도 `tdy_lspft`에는 반영되지 않습니다.** (실측 2026-07-31) 매도가 있는 날은 직접 재계산해야 합니다.

```
kt00017.sell_amt > 0 인가?
  → ka10076 (당일 체결 목록) 에서 종목코드 수집
  → 각 종목 ka10077 호출 → tdy_rlzt_pl 합산
```

매도가 없는 날은 `tdy_lspft`(=0)가 정확하므로 추가 호출이 필요 없습니다. 조건부로 돌리세요.

### 4. 0이 두 가지 의미를 가진다

`sell_amt > 0`을 확인하고 재계산에 진입했는데 합계가 0으로 나왔다면, 그건 "없음"일 수 없습니다. **반드시 조회 실패**입니다. 로그를 남기지 않으면 원래 버그(`tdy_lspft`)와 구분이 안 됩니다.

```java
if (fills == null) {
    log.warn("[계좌] ka10076 조회 실패 — 0으로 표시되나 매도 없음이 아니라 조회 실패임");
    return 0L;
}
```

### 5. 부분 실패를 구분하라

4종 TR 중 일부만 실패했을 때 "전체 실패"로 처리하면 멀쩡한 데이터를 버리게 됩니다.

- `Optional.empty()` = **조회 실패**
- 빈 리스트 present = **실보유 0종목**

이 둘이 뭉개지면 "잔고가 비었다"와 "조회가 안 됐다"를 구분할 수 없습니다.

### 6. 계좌번호·잔고 마스킹은 필수

- 운영 INFO 로그에 **잔고 숫자를 찍지 마세요.** 값이 필요한 예시는 `********`처럼 가려서 다룹니다.
- DEBUG를 켤 일이 있으면 `kt` 접두 TR 응답은 마스킹하세요.
- 계좌 응답 원본(JSON)을 저장소·이슈·로그 첨부로 내보내지 마세요. 예수금·보유종목·평가금액이 그대로 들어 있습니다.

## 이번 글 정리

| 주제 | 핵심 |
|---|---|
| 엔드포인트 | 전부 `/api/dostk/acnt`, 읽기 전용 |
| 계좌번호 | body에 넣지 않음 (appkey에 귀속) |
| kt00018 | 총계 + 보유목록 1회 호출, `stk_cd`의 `A` 접두사 제거 |
| kt00001 | 예수금 상세 (`qry_tp="3"`) |
| kt00004 | 평가 현황, 단 `tdy_lspft`는 당일 실현손익이 아님 |
| `dmst_stex_tp` | `"KRX"`/`"NXT"`/`"SOR"` 문자열, 수량 재확인은 KRX 고정 권장 |
| 설계 | 호출 세트 분리, `Optional.empty()`와 빈 리스트 구분 |
| 보안 | 잔고 로그 금지, `kt` 응답 마스킹, 원본 JSON 반출 금지 |
